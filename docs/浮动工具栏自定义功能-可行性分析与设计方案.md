# 浮动工具栏自定义功能 — 可行性分析与设计方案

> 日期：2026-06-06
> 状态：草案

## 1. 背景与目标

随心按（siyuan-power-buttons）插件目前支持在顶栏、状态栏、编辑区面包屑、Dock 面板等表面放置自定义按钮。本方案旨在扩展插件能力，支持对 **选中文本后出现的浮动工具栏**（protyle selection toolbar）进行自定义，包括：

1. **禁用**原生浮动工具栏按钮（如不常用的文字样式、行内公式等）
2. **添加**自定义按钮（复用现有的 5 种 action 类型）
3. **重排**按钮的显示顺序

## 2. 可行性分析

### 2.1 SiYuan Plugin API 支持

SiYuan 插件 API 提供了 `updateProtyleToolbar` 生命周期钩子：

```typescript
// siyuan.d.ts:419
updateProtyleToolbar(toolbar: Array<string | IMenuItem>): Array<string | IMenuItem>;
```

**工作机制：**
- SiYuan 内核在每次构建浮动工具栏时调用此方法
- 传入当前 toolbar 数组（`string` 为原生按钮标识符，`IMenuItem` 为自定义按钮对象）
- 插件对数组拥有**完全控制权**：可 filter 删除、push/splice 添加、自定义排序后返回
- `"|"` 为视觉分隔符，同样可以增删
- 参考实现：siyuan-muse 插件（`src/index.ts:228-238`）

**结论：✅ API 完全支持，无技术障碍。**

### 2.2 原生按钮标识符

SiYuan 桌面端浮动工具栏默认包含以下按钮（来自 `Constants.PROTYLE_TOOLBAR`）：

```
["block-ref", "a", "|", "text", "strong", "em", "u", "s", "mark", "sup", "sub", "clear",
 "|", "code", "kbd", "tag", "inline-math", "inline-memo"]
```

| 标识符 | 功能 | 中文说明 |
|--------|------|---------|
| `block-ref` | Block Reference | 块引用 |
| `a` | Link | 超链接 |
| `text` | Font Style | 字体样式 |
| `strong` | Bold | **粗体** |
| `em` | Italic | *斜体* |
| `u` | Underline | 下划线 |
| `s` | Strikethrough | ~~删除线~~ |
| `mark` | Highlight | ==高亮== |
| `sup` | Superscript | 上标 |
| `sub` | Subscript | 下标 |
| `clear` | Clear Format | 清除格式 |
| `code` | Inline Code | `行内代码` |
| `kbd` | Keyboard | 键盘标记 |
| `tag` | Tag | 标签 |
| `inline-math` | Inline Math | 行内公式 |
| `inline-memo` | Inline Memo | 行内备注 |
| `\|` | Divider | 分隔符 |

移动端为精简版，缺少 `s`、`mark`、`sup`、`sub`、`kbd`。

### 2.3 与现有架构的契合度

| 现有能力 | 复用方式 |
|---------|---------|
| `PowerButtonsConfig.items` 配置体系 | 扩展 `SurfaceType`，新增 `"selection-toolbar"` |
| `PowerButtonItem` 数据模型 | 完全复用（id, title, icon, action, order 等） |
| `CommandExecutor` 命令执行器 | 直接复用，自定义按钮的 action 执行 |
| `NativeElementSuppressor` 思路 | 类似机制用于原生浮动按钮的禁用 |
| 设置界面预览面板 | 扩展 preview layout，增加浮动工具栏区域 |
| 配置导入/导出/迁移 | 扩展 sanitize 和 import-export |

### 3.2 核心管理器

新建 `src/core/surfaces/selection-toolbar-manager.ts`：

```typescript
export class SelectionToolbarManager {
  /** 原生按钮标识符 → 中文标题映射 */
  static readonly NATIVE_BUTTON_LABELS: Record<string, string> = {
    "block-ref": "块引用",
    "a": "超链接",
    "text": "字体样式",
    "strong": "粗体",
    "em": "斜体",
    "u": "下划线",
    "s": "删除线",
    "mark": "高亮",
    "sup": "上标",
    "sub": "下标",
    "clear": "清除格式",
    "code": "行内代码",
    "kbd": "键盘标记",
    "tag": "标签",
    "inline-math": "行内公式",
    "inline-memo": "行内备注",
  };

  /** 所有可配置的原生按钮标识符 */
  static readonly CONFIGURABLE_NATIVE_NAMES = Object.keys(SelectionToolbarManager.NATIVE_BUTTON_LABELS);

  /**
   * 自定义浮动工具栏
   * @param originalToolbar - SiYuan 传入的原始 toolbar 数组
   * @param config - 插件配置
   * @param executor - 命令执行器
   * @returns 自定义后的 toolbar 数组
   */
  static customize(
    originalToolbar: Array<string | IMenuItem>,
    config: PowerButtonsConfig,
    executor: CommandExecutor,
  ): Array<string | IMenuItem> {
    const disabledNames = new Set(
      config.disabledSelectionToolbarItems.map(item => item.name)
    );

    // 1. 过滤掉被禁用的原生按钮（保留分隔符和自定义按钮的清理逻辑稍后处理）
    let toolbar = originalToolbar.filter(item => {
      if (typeof item === "string") {
        return !disabledNames.has(item);  // 也过滤掉对应的 "|"
      }
      return !disabledNames.has(item.name);
    });

    // 2. 清理连续的分隔符和首尾分隔符
    toolbar = SelectionToolbarManager.cleanDividers(toolbar);

    // 3. 插入自定义按钮
    const customItems = config.items
      .filter(item => item.surface === "selection-toolbar" && item.visible)
      .sort((a, b) => a.order - b.order);

    for (const item of customItems) {
      toolbar.push({
        name: `power-buttons:${item.id}`,
        icon: getIconMarkup(item),
        tip: item.tooltip || item.title,
        click: (protyle) => {
          void executor.execute(item);
        },
      });
    }

    return toolbar;
  }

  /** 清理多余的分隔符 */

}
```

### 3.3 插件入口钩子

在 `src/index.ts` 的 `SiyuanPowerButtonsPlugin` 类中实现：

```typescript
updateProtyleToolbar(toolbar: Array<string | IMenuItem>): Array<string | IMenuItem> {
  return SelectionToolbarManager.customize(
    toolbar,
    this.configStore.getConfig(),
    this.executor,
  );
}
```

### 3.4 SurfaceManager 集成

`selection-toolbar` 类型的按钮不需要创建 DOM 元素（由 `updateProtyleToolbar` 钩子管理），但需要在 `render()` 中被识别：

```typescript
// src/core/surfaces/surface-manager.ts
render(config: PowerButtonsConfig): void {
  // ... 现有逻辑 ...

  for (const item of visibleItems) {
    // ... 现有 surface 处理 ...

    if (item.surface === "selection-toolbar") {
      // 浮动工具栏按钮由 updateProtyleToolbar 管理，无需 DOM 操作
      continue;
    }
  }
}
```

## 5. 风险与注意事项

| 风险 | 等级 | 应对策略 |
|------|------|---------|
| `updateProtyleToolbar` 被多个插件同时调用时的冲突 | 低 | 每个插件独立接收和返回数组，SiYuan 内核按插件加载顺序串联调用 |
| 移动端 toolbar 列表不同 | 低 | 管理器按实际传入的数组操作，无需特殊处理 |
| 分隔符清理逻辑不当导致 UI 异常 | 中 | 单元测试覆盖各种边界情况 |
| 原生按钮标识符在 SiYuan 版本间变化 | 低 | sanitize 时检查标识符有效性，无效的自动移除 |
